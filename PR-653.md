Replaces #651. The hourly Upstream item data job copied upstream's item and stat files whole, so every run would drop what woke added by hand: Facetor's Lens (#627), the launch-day 3.30 stats, our stat refs, plus the scarabs, coins and Captured Beasts upstream removed but the trade site still lists. #651 failed 25 unit tests that way.

## What changes
- `scripts/upstream-merge.mjs`: three-way merge per entry (items by namespace + refName, stats by ref). Base is upstream at the commit last taken (`.github/upstream-data.json`).
  - woke-only entries and entries upstream dropped are kept
  - a stat upstream renamed (same trade id, e.g. "Nearby" → "within 6 metres") keeps our ref and gains upstream's wordings; renames are found in English and used for every language
  - wordings merge as a union, since items still carry old ones (Maven's Orrery); on map and area mods upstream's removals hold, as the map mod picker offers those lists whole
  - a wording the merge would put on two stats stays where we added it, else where upstream has it; an upstream stat left with no wordings that way is dropped and its trade ids join ours (2 cases: "+#% to Item Rarity", Towers cost)
  - trade ids: upstream's, with our additions and removals on top
  - renames are found against ours (ours' ref missing upstream, upstream's ref missing in ours, same trade id), so a kept rename is found again on every later run; base is normalized the same way as upstream's copy
  - entries upstream dropped are kept whole: every variant of a repeated item (Stormblood), every stat group it didn't split into single stats (Heist item quantity)
  - stat groups: a group upstream split into single stats goes when we never changed it, stays when we did (#434's granted-skill groups) and then upstream's new single goes; a new upstream group folding our single stats goes (our singles stay, as code reads them); a group only another language has replaces our unchanged singles there
  - repeated items (Precursor's Emblem variants) pair up by content, not position
  - other languages follow the merged English: stats English left out, or covered by ours, are left out there too
  - the job stops with an error if upstream's copy at the commit last taken is out of reach, rather than merging without a base
  - upstream's 86 placeholder pseudo stats (`"<ref> "`, every Temple room and increased rarity, trade option lost) are not taken, in any language
  - zero-width spaces are stripped from upstream's wordings (Parser.ts strips them from item text)
- `scripts/upstream-data.mjs` uses it, reports counts and any new wording/ref clashes in the PR body, and no longer touches `client_strings.js`: that goes with upstream's parser code (3.30 renamed `MAP_MORE_SCARABS`, which Parser.ts reads) and is only listed. The trade-data-patch re-run is gone; the merge keeps its output.
- Data merged from upstream 35b967e, **data version 25**. en stats: 58 new, 379 renamed (our ref kept). The PR report now also checks for stats with no wording, a trade id on two stats, and a ref or wording both in a group and on a single stat. en and cmn-Hant: none. Known leftovers: one trade id (Chance to Bleed's effect id) on a ru/ko locale-only group and a single stat, and the 3.30 rarity ids on ko's own "+#% to Item Rarity" group and our increased rarity stat. Both only affect reverse id lookups; wordings don't clash.
- Simulated the next run (upstream changes one line per language on top of 35b967e): exactly that line changes, nothing else.
- `map-mods.test.ts`: the Fungal Growths test used the pre-3.30 Blight Chest wording, which 3.30 removed (trade site confirms); `KNOWN_UNSEARCHABLE` 27 → 30 for upstream's new "100% Delirious" wording and the Towers mods becoming area mods.
