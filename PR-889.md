The Docs workflow's `deploy` job sometimes fails with "No artifacts named github-pages were found" (runs 711 and 715). The build and upload worked. `deploy-pages` then asked for the artifact 0.3 s after the upload in the same job finished, and the artifact wasn't listed yet.

- The workflow is now two jobs, `build` (build + upload) and `deploy` (`needs: build`), as in GitHub's own Pages workflow. The artifact is finished before the deploy job starts.
- Permissions move to the workflow level (contents read, pages write, id-token write), so `configure-pages` in the build job can read the Pages settings.
- The deploy step gets `id: deployment`, so the environment URL is filled in. It was empty before.

Only `.github/workflows/pages.yml` changes. It runs on master pushes, so the first master push after merge tests it.
