_Requested by **Guy** · [project thread](https://claude.ai/code/project/chan_01TFAVQEVFL8KKQ8fhVfpfJo?thread=cmsg_01TFAVQEVFL8KKQ8fhVfpfJoNsyLy214A7Ecanv8fCCaK7)_

A player on the public release got "OCR files missing: tesseract-core-simd.js, opencv.js, eng.traineddata" in Essence scan, and the message sent them to Awakened PoE Trade's releases page.

**What I found:** the 0.3.0 and 1.330.0 installers and portable builds all ship `resources/cv-ocr` with every file (checked by unpacking them). So on that player's PC the bundled copy was removed or hidden (an antivirus is the usual suspect), and the app had no way to recover. Guy's PC never shows this because `%APPDATA%\woke-poe-trade\apt-data\cv-ocr` already has the files.

**Fix**
- `ocrDir()` only picks a folder that has every file the worker loads (both `.js`, both `.wasm`, `eng.traineddata`), so a partial config folder can't shadow the installer's copy.
- When no folder is complete, the app downloads `cv-ocr.zip` once into `apt-data/cv-ocr` (Electron `net.fetch`, so the system proxy applies; unzipped with Windows' own `tar.exe`). This runs on the OCR check, scan start, essence read and death recap read. A failed download waits 5 minutes before the next try.
- The error now says why the download failed and links our [OCR guide](https://guybnd.github.io/woke-poe-trade/ocr-guide), not APT's releases page.
- `docs/ocr-guide.md` says the app fetches the files itself and gives the folder path.

**Checks (local):** `npm run build` in main (tsc + bundle), `vitest run main` in testing (209 passed, including the new `ocr-dir.test.ts`: folder choice, download and unzip, failure message and retry wait). Unzipping the real `cv-ocr.zip` with `System32\tar.exe` gives all files.
