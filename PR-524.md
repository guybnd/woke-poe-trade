The only sign of unsaved Atlas tree edits was a small "• Unsaved" in the tree's title bar. Guy picked U2 + W1 from the [mockups](https://claude.ai/artifact/DEizpeGcjgY8psHEGtagEU).

**On the tree (U2)**
- While the tree has unsaved edits, the Atlas tree window gets a gold frame.
- A label sits in the tree's top-left corner: "Unsaved", then Save (shows Ctrl S), then Discard. The mechanics list moves down below it. Nothing else on the tree moves.
- "Save as new" stays as an icon in the title bar.
- Strategy list rows with unsaved trees get an "Unsaved" tag.
- The tree panel now fills its body (`:scroll="false" fill`), so the bottom of the tree is no longer hidden under a scrollbar.

**Closing (W1)**
- These ask first while a tree has unsaved edits: the window's ✕, its tab, the tree's ✕, and the loadout's tree button.
- The question offers three choices:
  - "Keep editing" (Esc).
  - "Close without saving", which keeps the draft as before, so nothing is lost.
  - "Save and close" (Enter). With several unsaved trees it says "Save all and close".
- Going back to the game never asks, and it puts the question away.
- The question is on the overlay layer, centred on screen. The keyboard stays in it, and focus goes back where it was afterwards.
- A draft already answered with "without saving" isn't asked about again until it changes.
- A whole new config arriving (another window saving settings) never triggers the question.
