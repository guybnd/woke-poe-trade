Item text pasted into Ctrl+Space search or onto the rail failed when it came from poe.ninja, trade sites or PoB. Now it opens a price check.

Why it failed (Guy's Twilight Regalia from poe.ninja):
- No `Item Class:` line, and the parser refused text without one. It now accepts a copy that starts at `Rarity:`.
- Plain mod lines with no `{ … Modifier }` headings. The parser only reads mods under headings, so `pasted-item.ts` adds them: implicits come from `(implicit)`, crafted and fractured from their suffixes, and the explicits are the first section after the item level that has a matching stat. Lines are grouped the way the stat matcher reads them, so stats that span two lines stay together.
- `Searing Exarch Item` / `Eater of Worlds Item` each sat in their own section. The parser crashed on the empty section left once they were removed. They're now removed before parsing.
- PoB item text (no separators, `Implicits: N`) goes through PoB's own reader, which moves from `main/` to `ipc/pob-item.ts` so the renderer can use it, and then through `pobItemText`.

The game's own advanced copies pass through unchanged. All 36 item fixtures parse the same as before, except three plain copies that now read more mods.

Checks: an adversarial review found 6 issues: maps, multi-line stats, descriptions read as mods, Veiled crash, `Rarity:` searches, and crafted/fractured mods all labelled prefixes. The first five are fixed with tests. The prefix labelling is left as is; it's the same choice the PoB path already makes. Lint, vue-tsc and test typecheck pass, and the main and renderer builds pass. Full vitest: 4391 passed. 3 tests in `stash-optin.test.ts` failed in the full run; that file passes when run on its own.
