## Bug
Price checking Zorath's Eye of Malevolence from a "Related to" row said "Your filter hides this"; the real item from the game didn't.

## Cause
A price check opened by name gets text the app writes (`stackText`), which says `Item Class: Stackable Currency` for everything that trades in bulk. Zorath's Eye is a **Map Fragment** in game, so the chip matched it against currency rules (NeverSink's `currency restex`) instead of `fragments t2`. A filter that hides rest currency then said it was hidden.

## Fix
- `isStackText` recognises the app-written text (never a real copy, which has more sections).
- New `loot-filter/checked-facts.ts`: for such text, the item class comes from the filter itself (its `Class` beside `BaseType` lines, `filterClasses`), cached per filter doc. `example-item.ts` shares the cache.
- The chip uses `checkedItemFacts`.

## Tests
`test/woke/filter-checked-by-name.test.ts`: on NeverSink, the by-name Zorath's Eye now lands on the same rule as the real copy (fails before the fix: `currency restex` vs `fragments t2`), real copies and real currency unchanged. Local: targeted vitest, eslint on changed files, `typecheck:test` (no renderer errors).
