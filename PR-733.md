## Summary

Every row that names an item must show the game's item tooltip on hover. This adds a gate so new lists can't ship without one, and fixes the lists that already had none.

**The gate**
- `v-item-tip` (and so `WItemRow`) marks its element with `data-item-tip`.
- `testing/e2e/tip-audit.ts`: every fake-game test watches its page. Any visible text that is exactly an item's name (unique, base, gem, currency, card) and isn't inside an element with the item tooltip fails the test, listing where it was. Text in tooltips, menus and anything the mouse can't reach is skipped.
- A name that rightly has no item tooltip takes `data-no-item-tip="why"`. The reason is required.
- `renderer/test/woke/item-tip-rule.test.ts`: a static check that hand-wired `showTip(... kind: 'item')` sets `data-item-tip`, and that every exemption gives a reason.
- The rule is now in the repo's `CLAUDE.md` and the UI README.

**Gaps fixed**: Wickerman Viscera (with the Viscera tooltip), Disenchant bases, Scarab flip, Boss runs entry items, Drop counter (its right-click stays take-one-back via a new `noMenu`), Trade log, build compare and rare costs, loot filter (ground preview, item search, cluster headings, section headings, prices done rows), Ctrl+Space detail titles and lookup cards about items, launcher prices.

**Exempted, with reasons**: the price check's own heading and the new-item heading (the player is hovering that item), the loot filter's label swatches and sample card heading, player names, strategy names, app icon choices, and the trade currency filter radios.

Mod rows aren't detected automatically yet; the rule says to give them tooltips by hand.
