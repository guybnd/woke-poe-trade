Found while Guy tried the game-look preview. This PR has only the bug fixes, off master, so it can ship without #410.

**Search after opening a total.** Splitting a pseudo total (total Elemental Resistance → Fire/Lightning/Cold) or a local "2 mods" line built rows that held Vue proxies of the total's sources. Before searching, the price check snapshots the filters with `structuredClone`, and that threw `DataCloneError` on those rows. The search never started and the Search button stayed hidden, so old results stayed on screen as if they were current.
- `rawClone` (woke/raw-clone.ts) unwraps every level with `toRaw` before `structuredClone`. CheckedItem's snapshot uses it.
- `toggleSplit` builds the rows from the plain row (`toRaw`).

**Results go stale when the query changes.** CheckedItem now records the trade request when a search starts. Whenever the filters build a different request, `doSearch` drops and the Search button shows, even when the change lands in the same tick as a search.

**Crafted mods in a split.** A crafted mod split out of a total searched `crafted.*` only, which missed every item with the same mod rolled. It now searches the explicit stat, as fractured already did.

Tests: `test/woke/raw-clone.test.ts` (structuredClone throws on a split-style row; rawClone copies it). vue-tsc, eslint and `vitest test/woke` (3196 passed) are clean.
