## What
Follow-up to #791. In Ctrl+Space, "Where to get Fireball" (and other rows further down the list) showed no tooltip on hover.

**Cause:** `GameTooltip` hides the tooltip on any scroll (`window` scroll listener, capture), and `hideTip` cancels the pending show. A row hovered while its list is still scrolling stays `hovered`, so moving the pointer inside it never calls `enter()` again. The row stayed without a tooltip until the pointer left it and came back. Ways to hit it:
- Playwright's hover (and keyboard nav) scrolls the row into view first.
- A wheel scroll slides a new row under a still pointer.
- Moving the pointer while a smooth scroll is still running.

The data was fine: the gem rows' `{ name, type: 'SkillGem' }` builds a tooltip. Rows that need no scroll, such as "Where to get Herald of Ash", always worked.

**Fix (`ui/tooltip/item-tip.ts`):** one passive capture `scroll` listener on the document, next to the existing mouseover and mouseout pair. 150 ms after scrolling stops, the item row under the last pointer position gets its tooltip, and a different previously-hovered row is left. The pointer position comes from mouseover and is cleared when the pointer leaves the window.

## Tests
- e2e in `search-groups.spec.ts`: on the Facts chip it hovers "Where to get" gem rows below the fold and expects each gem's tooltip. It then wheel-scrolls under a still pointer and expects a tooltip when the row under the pointer is an item row. Before the fix the first hover failed.
- `openPalette` in that spec retries the hotkey until the palette mounts.
- Ran locally: item-rows, item-tip, listing-tooltip, title-tip, search and search-groups. All pass except one item-rows check, which waits for item art from the web CDN and can't load it from the cloud container.
