WOKEPOET-396, round two of shorter test runs. Guy approved all seven items. The full suite stays on every push to master, which releases are tagged from. The required check is still **Fake-game tests**.

**Faster for every PR**
- **S1:** 12 big spec files (loot-filter, tab-rail, atlas, dock-menu, trade, search, scarab, pob, price-check ×2, in-game, campaign) set `test.describe.configure({ mode: 'parallel' })`. Their tests now spread over shards; each test boots its own overlay.
- **S2:** 4 shards instead of 2. Locally, at 2 workers each: 1.3 to 1.9 min per shard.
- **S3:** `.github/actions/npm-deps` keeps node_modules by lockfile. It's used in the unit job, every fake-game job and the merge job.
- **Q1:** a PR that changes only `renderer/test/` skips the fake-game run.

**PRs test what they reach**
- **R1:** `testing/tools/ci-scope.mjs` reads the PR's file list.
  - It picks the specs `testing/e2e/scope.json` lists for the changed folders, plus a smoke set (toolkit, in-game).
  - Shared code runs every spec: the UI kit, main's woke core, the harness, fixtures and CI.
  - `testing/main/ci-scope.test.ts` fails if a spec has no entry.
- **R2:** the unit job runs `vitest related` on the changed files. Test helpers, data, packages, or a deleted file run all of them.
  - `vitest related` walks every page, so `vitest.config.mts` now resolves `/images/...` from `public/`.
  - The full unit run passes locally (4619).
- **Q2:** `woke-check local` picks the same subset, and `-Full` runs everything. DEVELOPING.md explains it.

**Measured locally:** for a single file, `vitest related` takes about 22 s on main code and 56 to 62 s on a module or the UI kit (55 to 57 test files). The full run takes about 147 s.

This PR changes CI itself, so its own run tests everything.
