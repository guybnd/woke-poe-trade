Fake-game tests failed twice in a row on #266 before any test ran. GitHub releases answered 504 for `electron-v40.10.6-linux-x64.zip`, and the same URL gave 504 from outside CI too.

- **Cache:** `actions/cache` keeps the zip in `.electron-cache` between runs. The key is main's lockfile, falling back to any earlier Electron cache. `electron_config_cache` points Electron's installer at that folder. Master's runs save the cache, and pull requests can read it.
- **Retry:** if the zip isn't cached, the download runs up to four times, waiting 30, 60 and 90 s between tries. The step fails only if all four tries fail.

Checked: the YAML parses, and a simulation of the retry loop under `bash -e` exits 0 when a try succeeds and 1 after four failures. Electron's `install.js` reads `electron_config_cache` as its cache root. This PR changes the workflow, so CI runs everything here, including the new steps.
