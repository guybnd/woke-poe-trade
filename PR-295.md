_Requested by **Guy**_

Fixes WOKEPOET-170 and WOKEPOET-171. Master (0.4.0) couldn't build an installer, so a v0.4.x tag would have failed.

## What was broken
1. `main/build/app-builder-lib+26.8.1.patch` stopped applying when #271 moved app-builder-lib to 26.18.0. patch-package exits 1 under `CI=true`, so `npm ci` in `main/` failed on every runner.
2. Even past that, `npm run package` failed: electron-builder 26.18 no longer depends on `7zip-bin`, which `build/fetch-ocr.mjs` uses to unpack the OCR files.
3. The Build workflow had been red (every run cancelled by fail-fast) since 2026-11-05, and nobody saw it.

## Changes
- Drop the patch (it only touched the Linux AppImage launcher), its AppImage test hook, and the Linux/macOS targets. Only Windows is released. patch-package and `postinstall` removed.
- Add `7zip-bin` as a direct dev dependency of main.
- Delete `.github/workflows/main.yml`; add a **Windows package** job to Tests. It uses the existing `changes` filter: runs when `main/` or a workflow changes, and always on master. When skipped it reports as passed, so it can be made a required check without blocking renderer-only PRs.
- DEVELOPING.md points at the current workflows.

## Checked locally (GUY-PC)
- `CI=true npm ci` in main: exit 0.
- `npm run build` and `npm run package -- --win -p never`: produce `Woke-PoE-Trade-Setup-0.4.0.exe` and the portable exe, with `resources/cv-ocr` (opencv, tesseract, traineddata) inside.
- test.yml parses; lockfile diff only removes patch-package's tree and adds 7zip-bin.
