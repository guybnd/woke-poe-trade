A player who runs PoE as admin gets "PoE runs as admin" and then "no clipboard data" on Ctrl+D, and has to restart the app by hand each time.

## What changes
- The existing no-access popup (shown only when the game window reports no access) is now a message box with **Restart as admin** / Not now and an **Always start as admin** tick. Dev builds and the portable exe keep the old text-only box.
- Restart as admin: `powershell Start-Process -Verb RunAs` (UAC). Declining keeps this copy running. On success this copy quits; the elevated copy gets `--woke-after-pid=<pid>` and waits (max 20 s) before taking the single-instance lock, so only one copy runs and the old config flush lands first. `relaunchArgs` drops that flag so normal restarts never wait.
- A downloaded update doesn't install on the way out (new `onPlainQuit` hook in AppUpdater); it installs on the elevated copy's quit.
- Always start as admin (`alwaysAdmin` in woke-app.json, off by default): at `ready`, a non-elevated copy asks for elevation before anything opens. Still one UAC prompt per launch; a scheduled task to skip it is not done (offered as an option to Guy).
- Tray: Restart as admin + the tick, shown only while PoE is admin or the tick is on.
- No NEWS line on purpose: Guy wants this visible only to players whose game runs as admin. Release notes line added.

## Tests
- `testing/main/run-as-admin.test.ts` (args, wait flag, PowerShell quoting, whoami parsing), app-updater test for the plain quit.
- main `tsc --noEmit` clean. testing/main suite: all pass except atlas-shot and tree-fit, which fail the same way on master in this container.
