Every `title` hover in the overlay now shows in the app's own tooltip card instead of the browser's grey Windows tooltip. That covers about 800 hovers in 176 files, plus any added later. Nothing changes per element.

## How it works
- `ui/title-tip.ts` adds one set of listeners for the page. While the pointer is on a titled element, the title is taken off it, so the browser has nothing to draw. The card shows under the pointer after 450 ms, or at once when moving straight from one title to the next. The title goes back on when the pointer leaves.
- The card uses the same look as the `WInfo` "?" card and is sized to its text, up to 300 px. It never covers a `WInfo` card or the item tooltip.
- A press, the game taking focus, a scroll or a drag hides the card until the pointer leaves. A `:title` that Vue changes while hovered is followed. Nothing shows during a drag.
- To opt out, put `data-native-title` on the element or a parent. `title=""` silences titles further up, as in the browser.
- It installs from a new `ui/page-hooks.ts` chunk, together with the number wheel. Startup JS ends up smaller than master's.
- Settings Close: its art CSS keyed off `title="Close"`, so the button hid itself on hover in the game look. It now keys off its X icon.

## Tests
- New `testing/e2e/title-tip.spec.ts`, registered in `scope.json`. It checks that the card shows under the pointer with the title off, that the title comes back on leave, that a press hides the card with no grey tooltip after a nudge, and that the settings Close button stays put.
- The harness keeps native titles unless a spec passes `titleTips: true`, so the existing `getByTitle` lookups still find hovered elements.
- `placeAtPointer` has unit tests.
- Two rounds of adversarial bug review; every finding is fixed.
