Follow-up to #949 (rancid bug hunt leftover).

## Problem
The "Run setup again" window held a full copy of the config from when it opened and saved all of it (loud `saveConfig`) on Finish. Anything the overlay saved quietly meanwhile (tool windows, keys, seen What's new) was overwritten.

## Fix
- New op `config-fresh`: main asks the overlay to flush (`config-flush`, waits up to 3s for `config-flushed`), waits for the store, and returns the file.
- Setup saves each pick as it's made: it upgrades the file on disk (`upgradedConfig`), three-way merges its own changes since its last save into it (`mergeConfigs`), and follows a newer config that arrives mid-save.
- A file that exists but won't upgrade is never written over; a failed save keeps setup open and shows "Couldn't save: …".

## Tests
- New e2e `toolkit.spec.ts` › "setup never saves its old copy over what the overlay saved meanwhile" (fails without the fix).
- vue-tsc, main tsc, renderer unit suite (5809 pass), toolkit e2e pass locally.
