Part 3 of the layout audit (epic WOKEPOET-491, subtask 495 for the gate). It also covers Guy's ask from the project chat: Ctrl+Space search can be resized.

## Layout gate
- With `WOKE_LAYOUT_GATE=1` (on for the fake-game e2e jobs), the layout checker runs in every test, without screenshots or red marks.
- A test fails on a new fault in `GATED_RULES`:
  - `clipped`: text cut off
  - `spill`: a box out of its window
  - `scroll-x`: a sideways scrollbar
  - `row-wrap`: a button row that wraps
  - `tiny-text`: text under 11px
- Known faults are listed in `testing/e2e/layout-baseline.json`, keyed by rule, widget type and DOM path.
  - It has 20 lines, the union of two full local runs. They're mostly the price check rows saved for the P1 redesign and the Ctrl+Space action row saved for S1.
  - The list only shrinks.
  - `WOKE_LAYOUT_GATE=write` writes what a run finds to `layout-baseline.new` (gitignored) instead of failing.
- To avoid flakes:
  - A fault counts only once it has been on screen for 0.7s, measured per fault and keyed by rule and place rather than text.
  - The harness asks the page to finish any pending second look before it reads faults, at test end and before a reboot.
  - The config is set before the page loads, so faults found during boot name their widget type. The default-config capture page is ignored.
  - `.sr-only` text is skipped.
- Cost, measured locally on the full suite of 465 tests: 8.3 min with the gate against 7.9 min without, about 5%. A full gated run after regenerating the baseline had no gate failures. The failures it did have were the same local load flakes the ungated run had.

## Ctrl+Space resizes
- The palette resizes from the right edge, the bottom edge or the bottom-right corner. It is centred and can't move, so it grows twice the drag and the corner stays under the mouse.
- It can't be shrunk below 576×288. WPanel now takes `min-width` and `min-height`.
- It keeps its size, and right-click › Reset size restores it.
- The test in `search.spec.ts` covers:
  - the corner staying under the mouse
  - more room, not bigger text
  - the minimum size
  - the size surviving a reopen
  - Reset size

## Review
A separate adversarial review found these, all fixed in 3c00c6d:
- Faults still waiting for their second look were dropped at test end.
- Fault keys were sometimes raw widget ids because the config was set late.
- Text-keyed confirms never confirmed ticking labels.
- Confirms could land under 0.7s.
- A confirm was lost during a screenshot.
- The resize edge moved at half speed.
- No minimum size.
