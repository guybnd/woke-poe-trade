Part 3 of the layout audit (epic WOKEPOET-491, subtask 495 for the gate). It also has Guy's ask from the project chat: Ctrl+Space search can be resized.

## Layout gate
- `WOKE_LAYOUT_GATE=1` is on for the fake-game e2e jobs. With it, the layout checker runs in every test, without screenshots or red marks. A test fails on a new fault in `GATED_RULES`:
  - `clipped`: text cut off with nothing to show the rest
  - `spill`: a box out of its window
  - `scroll-x`: a sideways scrollbar
  - `row-wrap`: a button row on two lines
  - `tiny-text`: text under 11px
- Faults the app already has are listed in `testing/e2e/layout-baseline.json`, keyed by rule, widget type and DOM path. There are 6 today, from a full local run. The list only shrinks. `WOKE_LAYOUT_GATE=write` writes what a run finds to `layout-baseline.new` (gitignored) instead of failing.
- To keep it from flaking, a fault counts only if a second scan 0.7s later still finds it. A first sighting schedules that scan, so frames caught mid-animation or mid-resize don't count. `.sr-only` text is skipped.
- Cost, measured locally on the full suite (464 tests): 8.3 min with the gate against 7.9 min without, about 5%. The local failures were the same load flakes in both runs (dock-menu undo, map-history, map-mods-scan, scarab-flip outlines). None came from the gate.

## Ctrl+Space resizes
- `WidgetSearch.vue` no longer turns resizing off. The palette resizes from any edge or corner and grows from the centre, giving more room rather than bigger text. It keeps its size and right-click › Reset size restores it.
- The new test in `search.spec.ts` covers the drag, the font staying the same, the size surviving a reopen, and Reset size.
