On 2026-11-24 the dev overlay took every click in the game, and it couldn't be reproduced afterwards. This PR makes sure the clicks always come back to the game, and logs enough to find the cause if it happens again.

## Audit: ways the clicks could stay taken
- **The mouse hook goes quiet** (Windows drops a low-level hook that answers too slowly, or the hook dies after sleep): `isMouseTaken` only cleared on a hook mouse move, so it stayed true forever.
- **The overlay gets focus with no zone under the cursor** (the window `focus` handler → `assertCardActive`): the card was released only from hook moves over zones. With no zones, nothing released it.
- **A reload left the old page's hover zones in main.** Owner ids restart at 1, so zones that never got re-registered kept catching the mouse where nothing shows any more. The dev build reloads after every merge.
- **The overlay page crashes while holding the mouse**: nothing was left to let go of it.

## Changes
- **Failsafe** (`OverlayWindow`): while the window takes clicks and the overlay isn't open on purpose, it checks `screen.getCursorScreenPoint()` every 500 ms. After 1.5 s with the cursor off every activate zone, the clicks go back to the game. It waits while a mouse button is held, because uiohook reports no moves during a drag (capped at 30 s). No timer runs while the game has the clicks, or while the overlay is open on purpose.
- **Rescue hotkey Ctrl + Shift + Alt + Space**: always registered, and re-registered after `unregisterAll`. It forces click-through, drops every hover zone and asks the page to resend its live zones (`woke-hover-resend`). It's listed under Settings > Hotkeys > Overlay, and the clash checker refuses it as an action key.
- **Reload drops the old page's zones**: it keeps the mouse position, so a cursor resting on an icon is still seen as on it.
- **Crashed overlay page** → `forceClickThrough`.
- **State log**: every change of overlay / card / mouseTaken / clickThrough is logged once, with the reason. That includes the library's own `setIgnoreMouseEvents` calls, which are wrapped. When the failsafe or the hotkey steps in, the log also lists the click zones and how long ago the hook last saw the mouse.

## Checks
- 11 new unit tests in `testing/main/overlay-click-safety.test.ts`.
- `vue-tsc` (app + tests), `tsc` (main), eslint on the changed renderer files, and `vitest related` (1065 tests) all pass.
- A separate adversarial review found 1 important issue (the failsafe cut drags off) and some nits. All are fixed except one limit: if the renderer itself keeps registering an invisible activate zone, the failsafe treats a cursor resting on it as legitimate. The new log will show such a zone by id and rect.

No NEWS line: this is a safety fix, not a tool feature. The hotkey is listed in Settings and in the release notes.
