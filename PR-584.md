One-off features audit, finding 8 (WOKEPOET-362).

## What
- **`ui/window-keys.ts`**: `useWindowKeys(el, { undo, redo, save, close, back, forward }, { shown, undoAnywhere, closeAnywhere })`. One rule for every window:
  - Ctrl+Z undo, Ctrl+Y or Ctrl+Shift+Z redo (Cmd too), skipping text fields and leaving Ctrl+Z to an Undo note on screen.
  - Ctrl+S save from inside the window (a field too).
  - Esc close; mouse back / forward through `useMouseNav`.
  - `windowKeyAction` is the pure decision; `windowKeyHelp` the list.
- **WPanel `keys`**: a "?" in the title lists the window's keys.
- Moved onto it:
  - Loot filter editor: same behaviour as before, now with its "?" list.
  - Settings: Esc closes, the search box's Esc still clears it first.
  - Atlas tree map: Ctrl+Z / Y / S as before, plus Cmd and Ctrl+Shift+Z for redo.
  - Session analytics, run timer, Regex library, deck history: mouse back, and the "?" list on the three with a panel.
- **Undo notes**: a window that took Ctrl+Z (Atlas tree) no longer also undoes a note, and Ctrl+Shift+Z never undoes a note (it redid nothing in the filter editor while a note was up).

## Left as is
- Esc in the app goes to the game first (main process); the Esc rules matter in the browser build and tests, as before.
- No Alt+Left / Backspace "back": Atlas rows use Alt+Left and the rule list uses Backspace already.
