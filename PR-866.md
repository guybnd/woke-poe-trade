Master's Tests run on 24151994 went red on four fake-game tests. All four were test races under load, not app regressions. Two more surfaced while checking and are fixed too. Only test code changed.

| Test | Cause | Fix |
|---|---|---|
| price-check.spec:125 (and every first Ctrl+D that expects the instant card) | The card or window is chosen at keypress from the poe.ninja prices loaded then. Pressed while the boot's download ran, it opened the window. | `harness.copyItem`: the first price check after boot waits for an in-flight poe.ninja download plus 300 ms. |
| glance-bar-drag:21 | It polled for a non-null `glancePos`, but the test starts with one saved, so it passed before the save. Second boot: the map line could arrive before the widget listened. | Poll for the new x value. Enter the map again until the bar shows. |
| price-check-poe-mode:157 | Moving the mouse from the lines onto Search searches by itself and removes the button, so the click waited until the 45 s timeout. price-check.spec:294 already documents this. | `dispatchEvent('click')`. |
| atlas-strategies:430 | Every boot downloaded GGG's atlas export live from raw.githubusercontent.com. Under CI load it went past the 30 s wait for the tree. | `page.route` serves the export from a cache that downloads once per worker. |
| card-drops:26/47 (found while testing) | Ctrl+Space pressed before the palette's lazy chunk listened: the overlay opened with no palette. | Wait for the palette's element, then press. |
| price-check.spec:294 (found while testing) | The chip width was measured once: 66 px against 72 px later. | Measure after `document.fonts.ready`. This cause is a best guess. |
