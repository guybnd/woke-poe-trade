## What broke

PoE refused the whole saved filter: `Line 331: Unable to parse parameter for BaseType rule: No base types found exactly matching "Dual Strike of Ambidexterity"`. Filters only know a transfigured gem by its base gem (NeverSink itself uses `TransfiguredGem True`), but the "gems in your build" rule copied the full name from PoB.

## Fix

- `gem-bases.ts`: `renameBases` moves transfigured gems out of any BaseType list into a copy of the rule, placed just before it, that names them by their base gem (game data's `normalVariant`) with `TransfiguredGem True`. Plain names stay in the original rule, so a rule for one transfigured gem never widens to the plain gem. A rule that is already `TransfiguredGem True` is renamed in place; `TransfiguredGem False` drops the names. `composeFilter` runs it before the safety net reads the rules and again last, over every rule, so no writer can bring the name back.
- Preview: `ItemFacts.filterBase` carries the base gem, and the matcher uses it for BaseType, so the card shows what the game will do with a transfigured gem.

## Review

Adversarial review found the first version widened rules (a Hide pinned on one transfigured gem would hide every Dual Strike); fixed by the split above. Known limit: the item card's "also listed in" and move options compare the full transfigured name, so they don't list these rules for a transfigured gem.
