_Requested by **Guy**_

Option B from WOKEPOET-154 (3.30 readiness epic WOKEPOET-149): our own 3.30 data, without waiting for upstream Awakened PoE Trade.

**`scripts/trade-data-patch.mjs`**
- `snapshot` saves the trade site's stat, item and exchange lists. The 3.29 snapshot is committed in `scripts/trade-baseline/`.
- `check` / `apply` fetch the live lists, diff them against the snapshot, and patch `renderer/public/data/en/{stats,items}.ndjson`:
  - a new stat id adds a stat matched by its trade text (one stat per text, holding every kind's id)
  - a stat id whose text changed adds the new text as another matcher of our stat with that id (3.30's "nearby" becoming metres)
  - a new unique, base (jewel, ring, amulet, belt, flask) or exchange item adds an item. Other new bases are listed to add by hand.
- Only the snapshot difference is used. Diffing the trade lists against our data directly would add about 5,500 stats upstream leaves out on purpose.
- Today's dry run against the live 3.29 lists changes nothing. File line ends are kept, and an unchanged round trip is byte-identical.

**`scripts/upstream-data.mjs`**
- It now only copies a file upstream itself changed since the last commit it copied. Otherwise the hourly job would open a PR reverting our patch with upstream's old copy.
- Tested against a fresh upstream clone, with and without a locally patched file.

**Launch day:** `node scripts/trade-data-patch.mjs apply`, then `node renderer/src/assets/bump-data-version.mjs`, then commit. Players get it without a release. Other languages keep upstream's text.
