## Cause

`e2e/loot-filter.spec.ts` kept timing out at 45 s on unrelated branches (PRs 710, 720, 721; shard 2/4), passing on rerun. The failure snapshots show the overlay with no loot filter widget at all: the editor never opened.

A seeded widget's hotkeys are registered by main straight from the saved config at boot, but the widget itself is a lazy chunk (`lazy()` in `renderer/src/web/woke/index.ts`) and only listens for `widget-action` once it has mounted. `openEditor` waited only for `Alt+Shift+F` to be registered, so under load the key was pressed into nobody and lost. The Alt + F sample card tests failed the same way.

## Fix

`Overlay.boot` now waits for each seeded widget's `#widget-<id>` element (set on the component root once it has mounted), bounded at 15 s and non-throwing, before returning. Every widget component renders a single root through `<Widget>`, so the wait ends as soon as the widget is in.

## Checks

Cloud run of the loot filter spec, 4 workers on 4 cores, `--repeat-each=2`, no retries:
- before: 15 failed, 49 passed (5.0 min), all with the editor or sample card never showing
- after: 64 passed (1.4 min)
