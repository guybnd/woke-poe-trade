## Why
The price check's Size control (palette in the title bar, and Price check window size in Settings) sets the root font size. Only rem lengths followed it. Woke text is px × Text size, so at 125% about two thirds of the price check's text stayed at 100% (measured: 13px rows stayed 13px). The item tooltip, one shared popup, was zoomed by Panel size × UI size and ignored Size.

## What
- `[data-w-window-sized]` goes on the windows Size sizes (price check + its side column, map check, Settings). It declares the text tokens (`--w-fs-*`, `--w-row-h`, `--w-ctl-h`, caps, with the theme/density/look variants) again as Text size × `--w-window-size` (fontSize / 16).
- `rem × --w-text-scale` lengths now use `--w-text-user` (Text size alone), because rem already holds Size.
- `tipZoom(target)`: a tooltip from a sized window takes that window's `currentCSSZoom` × Size. Everywhere else it uses `--w-ui-scale`, as before. The tooltip's rem widths are now px so they don't grow twice.
- The stat column fit in TradeListing counts Size into the text scale.
- Bug fix, so no NEWS line. release-next-notes line added.

## Review
A separate adversarial review found that `data-w-sized` was already used by WPanel for panels with a set height, so I renamed the attribute. It also found one more rem × text-scale spot (the FilterModifier roll input), now fixed. Still open, out of scope here: the instant ninja card, title tips and help cards don't follow Size yet.
