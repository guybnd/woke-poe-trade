## Why
The price check's Size control (the palette in the title bar, or Price check window size in Settings) sets the root font size. Only rem lengths followed it. Woke text is px × Text size, so at 125% about two thirds of the price check's text stayed at 100% (measured: 13px rows stayed 13px). The item tooltip, title cards and help cards are shared popups zoomed by Panel size × UI size, and they ignored Size.

## What
- `[data-w-window-sized]` is set on the windows Size sizes: the price check and its side column, the instant ninja card, map check and Settings. It redeclares the text tokens (`--w-fs-*`, `--w-row-h`, `--w-ctl-h`, caps, with the theme, density and look variants) as Text size × `--w-window-size` (fontSize / 16).
- Lengths written as `rem × --w-text-scale` now use `--w-text-user` (Text size alone), because rem already includes Size.
- `popup-zoom.ts` `tipZoom(target)` decides how big a popup is. A popup from a sized window takes that window's `currentCSSZoom` × Size; anywhere else it uses `--w-ui-scale`, as before. The item tooltip, title cards (`title-tip.ts`) and "?" help cards (`HelpCard.vue`) all use it. The tooltip's rem widths are now px so they don't grow twice.
- TradeListing counts Size into the text scale when fitting its stat columns.
- This is a bug fix, so there's no NEWS line. A line is added to release-next-notes.

## Review
A separate adversarial review found two problems, both fixed. `data-w-sized` already meant a WPanel with a set height, so the new attribute is now `data-w-window-sized`. One more rem × text-scale spot (the FilterModifier roll input) was still multiplying by Size twice. The review also found the instant card, title tips and help cards didn't follow Size; they are now included.
