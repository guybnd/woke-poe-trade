This PR follows up on Guy's Diagnostics numbers ("Prices: save to history" 1541 ms, "Overlay busy" up to 1384 ms, first paint at 7.9 s).

## What the numbers were

- **"Prices: save to history"** is the wall time of a background save, not an overlay freeze. Each save sent the ~11,000-item list twice (a snapshot plus the day rows, about 3 MB). Main then re-merged and rewrote the day's 2 MB file. Half of the saves repeated the last prices, because every overlay start replays them. On disk, 4 of today's 8 Covens snapshots were copies of the one before.
- **"Death recap: map mod list"** is OCR in a worker, so it doesn't block the overlay either.
- **First paint at 7.9 s** comes from the dev build, where vite serves loose modules. The production build gets the app on screen in about 0.2 s (`npm run test:perf`).
- **The overlay freezes:** a CPU profile of the live overlay caught the loot filter's safety net, which checks every priced base against the filter on load and on price updates. That took 400-500 ms per rebuild in the dev build.

## Changes

- `market-save`: main builds the day rows from the snapshot, so the renderer sends the list once. When the prices repeat the last snapshot on the same UTC day, main still writes the snapshot (movers and "saved at" go by snapshot times) but skips re-merging the day rows. Day rows are now written before the snapshot, so a snapshot on disk always has its day rows.
- `match.ts` `byBase`: walks each base only through the rules that could take it. Rules whose exact `BaseType ==` list leaves the base out are always false, so the verdicts are identical. `auditBases` and `stackNet` use it. In a microbenchmark on NeverSink regular with 2,647 bases, it's 1.8x faster.

## Checks

- New tests:
  - `filter-match-by-base.test.ts`: every listed base, plain, unique and stacked, in brief and full walks, matches the whole-filter walk on two strictness levels.
  - `testing/main/market-store.test.ts`: day rows, repeats, new days.
- Renderer unit tests (4422), testing/main tests (236), vue-tsc, main tsc and eslint all pass.
- An adversarial review found two problems in the first price commit (a failed day write could be skipped for good, and skipping whole saves broke movers' snapshot times). Both are fixed in the third commit. It found no problems in `byBase`.
