Guy asked for a new public release once the current queue (#317, #319, #320, #321) is in. This PR merges last.

## Version
`main/package.json` and lines 3 and 9 of `main/package-lock.json` go from 0.4.0 to 0.4.1.

## One draft per release
Every release so far left a second draft with only the `.blockmap` on it (v0.1.0 through v0.4.0). electron-builder uploads the installer, the portable exe and the blockmap in parallel, and when no release exists yet, each upload creates its own draft. `release.yml` now creates the draft before packaging, so all the uploads find it.

After the checksums are uploaded, a new check fails the run if the tag has more than one draft, or if any of these is missing: Setup exe, blockmap, portable exe, `latest.yml`, `SHA256SUMS.txt`.

## Publish from a manual run
Cloud sessions can't push tags. `workflow_dispatch` on master now takes `notes` and `publish` inputs. It drafts `v<version>` at that commit with the notes, and with `publish` set it publishes once the check passes. GitHub creates the tag when the release is published. Pushing a tag still works the same as before.

Not changed: the old blockmap-only drafts for 0.1.0 to 0.4.0 are still there. They can be deleted on the releases page.
