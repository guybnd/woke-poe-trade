WOKEPOET-177: a switched-off tool's code no longer loads.

- Every woke widget's spec (type, instances, defaults) moves to `renderer/src/web/woke/widget-specs.ts`. Each SFC's non-setup block re-exports its spec, so `component.widget` still works everywhere.
- The registry wraps each component in `defineAsyncComponent`. The overlay already mounts only widgets of switched-on modules (`OverlayWindow.vue`), so an off tool's chunk is never fetched.
- **Startup JS: 2,204 KB → 1,583 KB.** The `bundle.startupJs` budget drops to 1,640.
- **Hotkeys:** widgets fill in config defaults, their hotkeys among them, when they mount. The overlay sends main its hotkeys once at start, which is now before a lazy widget is in. So the hotkeys are sent again 50 ms after a widget's code loads, batched. Without this, `death-recap.spec` (Alt + M) and `toolkit.spec` (Alt + E) failed.
- **Fix exposed by the new mount order:** the PoB build detail read `campaign.state.gemsGot` before the campaign widget had made its state (`pob-builds.spec:164` threw). It now reads `state?.gemsGot`.
- **Perf budget:** `memory.listeners` goes 2,300 → 2,360. With every module on (the perf run), each lazy chunk's stylesheet is added as a `<link>`, and Vite's preload helper puts a load and an error listener on each: +52 with 26 chunks. Nothing else changed.
