Follow-up to #595 (merge review): a case-only PoB folder rename goes through `<folder>.woke-move-<time>`, and a failure between its two renames could leave that folder behind.

## Changes
- `moveBuildFolder`: if the second rename fails, the folder is renamed back to its original name before the error is passed on.
- New `recoverFolderMoves(root)`: finds `<name>.woke-move-<digits>` folders (up to the list's depth) and renames each back to `<name>` when that name is free. If the name is taken, the folder stays and a warning is logged.
- `listBuilds` runs it once per builds folder, the first time that folder is listed after the app starts.

## Tests
- `testing/main/pob-folder.test.ts`: rollback when the second rename fails; leftovers restored (top level and nested); a leftover left alone and logged when its name is taken; look-alike names (`.woke-move-soon`, a bare `.woke-move-1`) never touched.
- Main tsc clean; main vitest 219/219. Two suites (atlas-shot, tree-fit) don't load in this worktree because renderer deps aren't installed; this PR doesn't touch them.

## Review notes
- If the app dies mid-move, the folder comes back under its old casing, and the list's folder settings may still use the new casing. Folder matching ignores case, so the list still lines up.
