## What
Startup JS was 1640.07 KB against the 1640 KB budget, so any startup addition (even one What's new line) failed perf. A sourcemap breakdown of `index-*.js` showed the biggest single item was `pob-builds/gem-sources.json` (~105 KB, the campaign gem table), pulled in statically through `GameTooltip` → `gems.ts`.

- `gems.ts` now loads the table with a dynamic `import()` when the module runs, into a `shallowRef`. Every reader (tooltip, gem names, build panel, campaign build, loot filter build input) sits in a computed or template, so it updates when the chunk lands a moment after startup. The chunk is shared with Ctrl+Space's existing lazy load of the same file.
- Review follow-up: `useBuildRuleInput` returns null until the load settles, so the loot filter's safety-net auto-save can't write build rules without the build's gems. A failed load now logs a warning.
