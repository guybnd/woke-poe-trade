## What

After a price check search, tightening a stat range (raise a min, lower a max, tick a mod the listings show) filters the listings already loaded, with no trade search. Guy's design pick A from the mockups (recommended): hide rows that no longer fit, and say so in the Search row.

- `local-filter.ts`: `compareToSearched` rebuilds the trade request with each changed row put back to its searched range. If that equals the searched request, only ranges changed; each must be narrower (or a newly ticked stat) and readable from listings, else the results are stale. `listingFits` checks a listing with the stat-column readers.
- Search row: "Filtered here · N of M loaded fit" with Show/Hide N (hidden rows faded), or "Needs a new search" on dimmed results.
- The verdict reads only the listings that fit; it isn't logged under the search and doesn't blend an earlier check while filtered.
- The table and verdict keep their height while filtered, so the mods don't move.
- Never spends a search or fetch without a click (e2e counts the calls).
