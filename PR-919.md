## What
`glance-bar-fields.spec.ts` "set to In maps…" failed about 1 run in 3 on master code (reproduced locally on 5ac2902 and c0791ee; passed every time alone or on 9beee61). It failed twice in a row on PR 914, which blocked it.

## Why
The three tests share one fake app, which keeps the maps and night each test saves. All three wrote the same fixed old lines (2026/11/05 15:00–15:03).

Since #916, each widget reads the log tail afresh instead of sharing the page's first read. Under load, the session widget can read the tail after the test's lines are written. When it does, it:
- skips those lines as older than the previous test's saved map;
- dedupes them when they arrive live;
- ends the night as quiet for 15+ minutes, because the lines are 20 days old.

So the bar never showed. The app's behaviour is right: old lines in the tail are an old night.

## Fix
Test only. Each test's lines are stamped just before now and later than the previous test's, with the same offsets, so the 2:01 map time still holds. 8 of 8 local runs of the file passed, against 2 of 3 failing before.

chip-settings-layout passes locally on master: 5/5 in the earlier batch, plus PR 914's latest runs.
