## What
Atlas strategies › Import now takes poeplanner short links (`poeplanner.com/a/6ROH`), alone or inside guide text.

## How
- `expandShortTreeLinks` asks `api.poeplanner.com/api/b/<id>` (what poeplanner's own `/a/` page does), which answers with the full code as plain text, and swaps in `https://poeplanner.com/atlas-tree/<code>` before the usual import. An unreachable link or a non-code reply shows "Couldn't open the poeplanner link …".
- The fetch goes through the main-process proxy; `api.poeplanner.com` is added to its allowed hosts (no CORS on that API).
- Import is guarded against a double click while the link is fetched.
- **Proxy fix:** the proxy dropped `content-encoding` (net.request decodes) but kept the upstream `content-length`, which counts gzip bytes. poeplanner sends gzip with a length, so the body was cut short and the Vite dev proxy crashed on "Data after Connection: close". The length is now dropped with the encoding.

## Checks
Lint, vitest (new short-link test), test typecheck, renderer build, main `tsc` pass locally. On the dev build: `/proxy/api.poeplanner.com/api/b/6ROH` returns the full code (150 nodes, all in the 3.30 data), through both the main server and Vite.
