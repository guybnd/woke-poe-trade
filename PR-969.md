## What
- **Profiles** in the loot filter editor: several named whole filters (source, strictness, edits, own rules, presets, price moves, safety net, build rules), each saved to its own `<name> (woke).filter`.
- A slim row of profile tabs above the editor's tabs: click to switch, + for a new profile or a copy, right-click a tab to duplicate, rename or delete (the .filter file stays).
- Switching keeps the profile you leave as it is (unsaved changes stay in it, written only if nothing of yours is unsaved), loads the other with its own undo steps and save points, then saves it and has the game load it (held until town with Reload when safe).
- Migration: existing config becomes profile 1 named after its current file; `legacyFile` keeps the same output name and undo history file, so nothing changes until a second profile is added. Renaming it moves it to `<name> (woke).filter`.
- Settings' "Where saves go" says a named profile saves to its own file.
- What's new line (`loot-filter-profiles`) with a Show me spot on the tabs; release-next-notes line.

## How
- The active profile keeps its settings on the widget itself (`PROFILE_KEYS` in `profiles.ts`); inactive profiles hold a deep copy in `profile.data`. Ids are never reused (`lastProfileId`).
- `outputName` follows the active profile and never lets the first profile's old file be another profile's. `history-file.ts` takes a doc key per profile and `switchTo` flushes then reloads.
- `store.switchProfile` bumps the load and strictness counters first so a strictness switch still loading can't land in the other profile, blocks strictness keys and the ladder during a switch, and resets the store's saved state.
