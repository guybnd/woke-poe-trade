## What
- **Profiles** in the loot filter editor: several named whole filters (source, strictness, edits, own rules, presets, price moves, safety net, build rules), each saved to its own `<name> (woke).filter`.
- Chip left of the source picker: switch, New, Duplicate, Rename, Delete (the .filter file stays).
- Switching saves the profile you leave, loads the other with its own undo steps and save points, then saves it and has the game load it (held until town with Reload when safe).
- Migration: existing config becomes profile 1 named after its current file, `legacyFile` keeps the exact same output name and undo history file, so nothing changes until a second profile is added. Renaming it moves it to `<name> (woke).filter`.
- What's new line (`loot-filter-profiles`) with a Show me spot on the chip; release-next-notes line.

## How
- The active profile keeps its settings on the widget itself (`PROFILE_KEYS` in `profiles.ts`), so the rest of the editor is unchanged; inactive profiles hold a deep copy in `profile.data`.
- `outputName` follows the active profile; `history-file.ts` takes a doc key per profile (`history` for id 1, `history-<id>` otherwise) and `switchTo` flushes then reloads.
- `store.switchProfile` resets the store's saved-state (savedEdits, timeline baseline, pending reload) so a switch is never recorded as an undo step or shown as unsaved.
